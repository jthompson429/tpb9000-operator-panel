# Sensor integration and local dashboard v0.2 plan

This is a post-v1 expansion. The completed environmental panel remains the
fallback behavior throughout development: failure or removal of any new sensor
must not stop BME280 readings, Wi-Fi recovery, or the local display.

## Hardware facts and constraints

- The exposed I2C terminal uses GPIO 8 (SDA) and GPIO 9 (SCL) and is already
  shared with onboard devices and the BME280.
- VEML7700 uses fixed I2C address `0x10`; INA219 provides configurable
  addresses and normally starts at `0x40`. These do not conflict with the
  current BME280 at `0x76`.
- INA219 measures bus voltages only up to 26 V. The intended monitored rail is
  12 VDC, which is within that range, but supply transients must also remain
  below 26 V. The supplied generic breakout is marked `R100`, indicating a
  0.1-ohm shunt. Its board-level current and shunt-power ratings remain
  unverified, so the expected maximum current must be established before it is
  inserted into the power path.
- The screw-terminal RS485 connection is routed through an RS485 transceiver on
  GPIO 43/44. It is not a raw 3.3 V UART connection.
- The CAN terminal is routed through a CAN transceiver on GPIO 15/16. It is not
  a second raw UART connection.
- The presence module is the Waveshare HMMD mmWave Sensor based on SXKMXXX0.
  It requires 3.3 V, averages about 50 mA, and exposes 3.3 V UART at 115200
  baud plus an `OT2` digital output. `OT2` is high for presence and low for
  absence. Version 0.2 should use `OT2`; UART remains available for setup and
  diagnostics but is not required for routine presence detection.
- The hopper sensor matches the A02YYUW/A0221WU/TD-A02-V2.0 automatic UART
  family: 3.3-5 V supply, 9600-baud UART output, 3 cm blind zone, 3-450 cm
  range, and approximately 100 ms reporting. Its four connector positions are
  VCC, GND, RX/mode selection, and TX, but the supplied cable color-to-pin
  mapping must be verified from the physical connector or vendor harness
  documentation before wiring.
- Current firmware controls the LCD backlight as a CH422G on/off signal. Smooth
  fading requires a verified PWM-capable hardware path; software must not
  simulate PWM by rapidly writing the shared I2C expander.
- The supplied 3-24 V piezo is treated as a self-oscillating active buzzer for
  planning purposes. It requires a transistor/isolated-output driver and an
  appropriate supply; it must not be powered directly from an ESP32 GPIO.
  Initial feedback will therefore be timed chirp patterns rather than pitched
  melodies. Final polarity and current draw must be confirmed before wiring.

## Recommended implementation sequence

1. **Status/API foundation** — live snapshot store, `/api/info`, and
   `/api/status`; unavailable future measurements remain explicit `null` values.
2. **INA219** — confirm monitored rail, maximum voltage, shunt value, current
   direction, and breakout rating; add a filtered one-second power sampler.
3. **VEML7700** — add one-second lux sampling and filtering. Keep brightness at
   100% until a real PWM backlight path is confirmed.
4. **Presence input** — use the Waveshare radar's `OT2` digital output and
   implement active/dim/idle states without deep sleep or Wi-Fi shutdown. A
   verified 3.3 V-capable input path is still required on the panel.
5. **Hopper UART** — identify a safe raw ESP32 UART connection, confirm the
   sensor harness pin order, then implement the 9600-baud frame parser. Do not
   attach the TTL sensor to the terminal-block RS485 or CAN pins.
6. **Hopper calibration** — persist configurable full/empty distances, median
   filtering, hysteresis, percentage clamping, and the six-segment gauge.
7. **Buzzer** — add only after choosing an electrically appropriate active or
   passive device and output driver.
8. **Local dashboard** — implement against API v1 on the future mini PC at
   `tpb9000-server.local`. The ESP32 remains independent and must continue its
   local display behavior when that server is absent.

## Hardware validation record

### INA219

- Breakout: generic INA219 with `R100` (0.1-ohm) shunt at address `0x40`.
- Measured load: operator panel and its low-voltage peripheral rail only.
- Supply: nominal 12 VDC.
- Calibration: 100 uA current LSB, 2 mW power LSB, approximately +/-3.2 A
  measurable range.
- First powered test: 12.250-12.253 V, 0.204-0.207 A, and 2.506-2.542 W.
- Result: positive current direction, stable filtered readings, live JSON API,
  and no interruption to BME280, display, or Wi-Fi behavior.

## Required hardware decisions

Before hardware-specific firmware is flashed, record:

- INA219 expected maximum current and whether it will monitor only the operator
  panel or additional loads.
- VEML7700 breakout vendor/model and intended mounting location.
- A verified panel-side 3.3 V digital input for the mmWave `OT2` signal.
- Ultrasonic sensor cable pin order and a verified panel-side raw UART receive
  pin.
- Buzzer polarity/current and the selected transistor or isolated output.
- Whether modifying the panel internally to obtain backlight PWM is acceptable.
